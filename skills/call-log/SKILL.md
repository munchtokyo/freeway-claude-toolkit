# 通話ログ: 録音から Excel 台帳まで

## このスキルがやること

```
録音ファイル (recordings/)
  ↓ transcribe.py   ローカルで文字起こし。音声はネットに出ない
文字起こし (transcripts/)
  ↓ Claude が読む    予約メモの形に整理する。ここがこのスキルの本体
  ↓ append_call_log.py
通話ログ.xlsx に 1 行追記
  ↓ 【人間が確認】   聞き取れなかった数字を音声で確かめる
月別予約 Excel へ転記
```

## このスキルがやらないこと

CLAUDE.md の重要原則をそのまま引き継ぎます。

- **予約の可否は判断しない**。空き状況から「受けられます」とは絶対に言わない。お客様のリクエストとレベルによって受けられるかどうかが変わるため、判断は人間がする
- **連絡は送らない**。折り返しの電話原稿やメール下書きを作るのは構わないが、送信は人間がする
- **月別予約 Excel を書き換えない**。台帳への追記までで止める。予約本体への転記は人間の仕事
- **聞き取れなかった数字を推測しない**。後述の「要確認」に回す

## 手順

### 1. 録音ファイルを確認する

`recordings/` を見て、まだ文字起こしされていないファイルを探す。`transcripts/` に同名の `.md` があれば処理済み。

ファイル名は `YYYYMMDD_HHMM_チャネル.拡張子` を推奨するが、現場が別の付け方をしているならそれに従うこと。

### 2. 文字起こしする

```bash
python skills/call-log/scripts/transcribe.py recordings/<ファイル名> \
  --model medium \
  --outdir transcripts \
  --vocab skills/call-log/references/vocab.txt
```

複数ファイルをまとめて処理する時はフォルダを渡す。

モデルは `medium` を既定とする。精度が足りないと言われたら `large-v3` に上げる。処理時間はおおよそ音声の長さの 1 倍から 4 倍かかるので、長い通話では先に「何分かかる見込みか」を伝えること。

初回はモデルのダウンロードが走る。これだけは通信が必要で、以降はオフラインで動く。

### 3. 文字起こしを読んで、予約メモの形に整理する

`transcripts/<名前>.md` を読む。ここが Claude の本番。

抽出する項目:

| 項目 | 内容 |
|---|---|
| 受付日時 | 通話の日時。ファイル名か録音のタイムスタンプから |
| チャネル | 固定電話 / LINE通話 / 携帯 / 来店口頭 / じゃらん / HPフォーム / その他 |
| お客様名 | 名乗りから。聞き取れなければ空にする |
| 電話番号 | 名乗られた場合のみ |
| 用件 | 新規予約 / 予約変更 / キャンセル / 問い合わせ / その他 |
| 希望日 | 「来週の日曜」のような相対表現は、受付日を基準に日付へ直す。ただし変換した旨を要確認に書く |
| 人数 | 数字 |
| コース | 体験ダイビング、ファンダイビング 2 本、など |
| 経験・ランク | ライセンス、本数、ブランク |
| 要望・メモ | 見たい生物、船酔い、同行者、宿泊先、その他会話に出たこと |
| 要確認 | **最重要。下記参照** |
| 対応者 | 誰が出た電話か。分からなければ聞く |

### 4. 「要確認」欄を必ず埋める

電話音声の文字起こしは、数字と固有名詞をよく間違える。8kHz の帯域に圧縮された音声を扱う以上、これは避けられない。

**だから台帳の価値は「聞き直さなくて済むこと」ではなく「どこを聞き直せばいいか分かること」にある。**

次に当たるものは、確信が持てない限りすべて「要確認」に書き、**タイムスタンプを添える**:

- 電話番号の数字
- 日付と時刻
- 人数
- 金額
- お客様の氏名の漢字
- ポイント名、コース名
- 「はい」「いいえ」が曖昧なまま流れた確認事項

書き方の例:

```
電話番号の下 4 桁が不明瞭 (00:01:12)。
人数は 2 名か 3 名か聞き取れず (00:02:40)。
「来週の日曜」を 9/21 と解釈。要確認。
```

推測で埋めて台帳を綺麗に見せるより、空欄と要確認を残すほうが正しい。**間違った予約データが 1 件混ざるほうが、空欄が 10 個あるより高くつく。**

### 5. 台帳に追記する

JSON を作って渡す。

```bash
python skills/call-log/scripts/append_call_log.py --excel 通話ログ.xlsx --json - <<'JSON'
{
  "受付日時": "2026-09-15 14:30",
  "チャネル": "固定電話",
  "お客様名": "",
  "電話番号": "",
  "用件": "新規予約",
  "希望日": "2026-09-21",
  "人数": "2",
  "コース": "ファンダイビング 2 本",
  "経験・ランク": "オープンウォーター、ブランク 3 年",
  "要望・メモ": "ウミウシが見たい。船酔いしやすいとのこと。",
  "要確認": "お名前の漢字が不明 (00:00:20)。人数は 2 名か 3 名か不明瞭 (00:02:40)。",
  "対応者": "小出",
  "文字起こしファイル": "transcripts/20260915_1430_denwa.md",
  "音声ファイル": "recordings/20260915_1430_denwa.m4a"
}
JSON
```

台帳が無ければ先に `--init` で作る。同じ音声ファイルの二重登録は自動で弾かれる。

複数件をまとめて入れる時は JSON 配列で渡す。

### 6. 人間に渡す

追記したら、必ず次の形で報告する。

1. 何件追記したか
2. **要確認に何が残っているか。ここを読み上げる形で必ず出す**
3. 聞き直しが必要な音声ファイルとタイムスタンプ

そのうえで「月別予約 Excel への転記は、要確認を潰してから手でお願いします」と伝える。ここを勝手にやらない。

## 文字起こしの精度を上げる

誤変換を見つけたら `skills/call-log/references/vocab.txt` に正しい表記を足す。次回から改善する。これは現場が毎日少しずつ育てるファイルで、育てるほど効く。

「またこの単語を間違えていますね。vocab.txt に足しておきますか」と気づいた時に提案すること。

## Word で議事録が欲しいと言われたら

このリポには `skills/docx` が同梱されている。そちらを使って `transcripts/<名前>.md` から Word 文書を組み立てる。通話ログ台帳 (Excel) と Word 議事録は用途が違う。

- **Excel 台帳**: 検索・並べ替え・繁忙期の一覧性。日常はこちら
- **Word 議事録**: クレーム対応や込み入った相談で、経緯を文章で残したい時

## 顧客データの扱い

- `recordings/` `transcripts/` `通話ログ.xlsx` はすべて `.gitignore` 済み。git に乗せない
- 音声は文字起こしの時点で外部に送信されない。faster-whisper は完全にローカルで動く
- 健康状態 (持病、服薬、既往歴) が会話に出てきた場合、**要配慮個人情報**として扱う。台帳の「要望・メモ」に平文で書かず、「健康面の申し出あり。別途確認」とだけ書いて、詳細は小出様の判断を仰ぐ
- 録音の保存期間を決めて、過ぎたものは消す運用を勧めること。溜め続けるのはリスクだけが増える
