# zenjitsu-renraku — 前日連絡フロー一式

## 目的

毎日夕方にやっている「翌日のお客様への連絡準備」を一括で下書きする。

現在の所要時間: 約 1 時間 / 日
目標: 約 20 分 / 日

---

## 出力する 4 種類（一括生成）

### 1. メール下書き（顧客別）

- 集合場所
- 集合時間
- 持ち物（コース別）
- 天候・海況予報
- 注意事項
- 当日連絡先

### 2. LINE 下書き（個人携帯 LINE 派のお客様）

短く、絵文字使い、フランクなトーン。

### 3. 電話原稿（電話派のお客様）

要点メモ。電話する時に見るための箇条書き。

### 4. Google Calendar 反映

- 翌日の予約をカレンダーイベントに登録
- 講師アサイン情報含む
- 休業日との競合チェック

---

## 入力パターン

### 通常の前日連絡

```
/zenjitsu-renraku
明日 6/15 の予約一覧を見て、連絡下書きを全部作って
```

### 翌日朝発生の急ぎ案件

```
/zenjitsu-renraku
明日朝一の田中さんに、急遽ポイント変更の連絡を入れたい。
ドラフト作って
```

---

## 内部ワークフロー

1. Sheets「予約台帳」から翌日分の予約を取得
2. 各予約について Sheets「顧客マスター」のカルテを参照
3. 連絡チャネル（メール / LINE / 電話）の判定（顧客マスターから）
4. 天候 API or 既存気象情報を取得（オプション）
5. 4 種類の下書きを生成
6. ファイル出力 or チャットに表示
7. **送信ボタンは押さない**（人間が確認してから個別送信）

## 重要原則

### 1. 自動送信は禁止

メール・LINE・電話、すべて下書きまで。送信ボタンは人間が押す。

### 2. 顧客の連絡チャネル選好を尊重

過去にメールで連絡していた顧客にいきなり LINE を送らない。顧客マスターの「連絡チャネル」列で判定。

### 3. 講師アサインを含める

「担当講師」を明記することで、お客様が「誰と潜るか」を事前に把握できる。リピーターは特に大事。

### 4. 天候・海況情報

可能なら気象 API を呼ぶ。難しければ「当日の天候判断は店舗側で行います」と書く。
