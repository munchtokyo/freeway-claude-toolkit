# yoyaku-merge — 予約 5 チャネル統合

## 目的

Freeway の予約は 5 つのチャネルから入ってくる:

1. HP 予約フォーム（既存 GAS 連携で Sheets に自動記録）
2. 電話
3. 現場で口頭
4. 個人携帯 LINE
5. じゃらん（OTA）

これらを Google スプレッドシート「予約台帳」シートに 1 つに集約する。

---

## 入力パターン

### パターン A: HP フォームの取りこぼし確認

```
/yoyaku-merge
今日の HP フォームからの予約、スプレッドシートに全部反映されてるか確認して
```

→ Sheets の予約台帳と GAS ログを照合。抜けがあれば指摘。

### パターン B: 電話・口頭で取った予約

```
/yoyaku-merge
今、電話で田中太郎さんから 6/15 体験コース 2名 リクエスト来た。
ライセンスなし、初心者、佐渡店、9:00 集合、宿は無し。
```

→ 構造化して予約台帳に新規行追加。

### パターン C: 個人 LINE のスクショから

```
/yoyaku-merge
~/Desktop/line_screenshots/2026-05-28.png のスクショ、予約として読み取って
```

→ 画像 OCR → 構造化 → 予約台帳追加。

### パターン D: じゃらん CSV のマージ

```
/yoyaku-merge
~/Downloads/jaran_2026-07.csv を予約台帳にマージして
```

→ CSV をパース、既存予約と重複チェック、新規分を追加。

## 重要原則

### 1. 予約自動受付はしない

空きの数だけで判断できない。お客様のリクエスト・レベルによって受けられる / 受けられないが変わる。

このスキルは「予約候補を整理する」までで、可否判断は人間。

### 2. ステータスは「仮」で入力

新規追加された予約は必ず `仮` ステータス。小出さんが内容を見て「確定」「キャンセル」に変更する。

### 3. 重複検知

同一来店日・同一氏名・同一連絡先の組み合わせがある場合は警告。

### 4. 顧客マスターとの紐付け

代表者氏名で顧客マスターを検索し、リピーターなら過去の顧客 ID を自動付与。新規なら新規顧客 ID 発行。
