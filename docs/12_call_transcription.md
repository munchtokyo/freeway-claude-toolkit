# 通話の文字起こしは現実的か (LINE 通話 / 固定電話)

**作成**: 2026-09-15
**位置づけ**: 川島の調査による叩き台。実際に採用するかは皆様の判断

---

## 結論

| 対象 | 現実性 | ひとこと |
|---|---|---|
| **固定電話 (0259-52-5781)** | ◎ 現実的 | 2,000 円台のアダプタ 1 個で解決する。今日からやれる |
| **LINE 通話** | △ 条件付き | LINE 側に録音の仕組みが無い。物理的に迂回するしかない |
| **文字起こし** | ◎ 現実的 | ローカルで無料・オフライン。顧客の声は外に出ない |
| **Excel / Word 保存** | ◎ 現実的 | 実装済み。`skills/call-log/` |

一番大事な前提を先に書きます。

**文字起こしは「聞き直しをゼロにする道具」ではありません。「どこを聞き直せばいいか分かる道具」です。**

電話音声は 8kHz に帯域を絞って圧縮した音です。人間の耳でも聞き返す数字を、AI が毎回正しく取れるわけがない。ここを勘違いしたまま導入すると、間違った予約データが台帳に入って、かえって事故が増えます。

だから `skills/call-log/` は「要確認」列を必ず埋める設計にしてあります。台帳の価値はそこにあります。

---

## 1. LINE 通話がなぜ機械的に無理か

### API が無い

LINE の Messaging API (公式アカウント向け) が扱えるのはテキスト、画像、スタンプ、それに**音声メッセージ**までです。**通話の音声を取り出す API はありません**。サーバー側で拾う道は存在しないと考えてください。

つまり「LINE 通話 × 文字起こし」を、プログラムだけで完結させる方法はありません。

### 端末側も塞がれている

LINE 自体に通話録音機能はありません。端末の OS 次第です。

| 端末 | 可否 | 方法 |
|---|---|---|
| **Android** | ○ | 標準の画面録画で、音声ソースを「メディア音声とマイク」にする |
| **iPhone** | × | OS の制限で、通話中の内部音声を他のアプリが録れない |
| **PC 版 LINE (Windows)** | ○ | PC の再生音とマイクを同時に録音する |

小出様は **iPhone で個人携帯の LINE** を使われている想定です。ここが一番塞がっている組み合わせになります。

## 2. LINE 通話をどうしても録るなら

### 案 A: スピーカーホン + 別の録音機 (推奨)

静かな場所で LINE 通話をスピーカーに切り替えて、横に IC レコーダーか古いスマホを置いて録る。

- **長所**: 端末も OS も選ばない。今日からできる。追加費用ゼロ (手持ちのスマホでよい)
- **短所**: 部屋の反響が乗るので音質は落ちる。周りが騒がしいと使い物にならない
- **向く場面**: 事務所の中で受ける LINE 通話

原始的に見えますが、**この方法は固定電話にも来店時の口頭予約にも同じように使えます**。1 台の録音機で 5 チャネルのうち 3 つをカバーできる。始めるならここからです。

### 案 B: Android に切り替える

業務用の LINE を Android 端末に移せば、標準の画面録画で通話が録れます。

- **長所**: 音質が安定する。操作が通話ごとに完結する
- **短所**: 端末を用意する話になる。個人の LINE を業務端末に移す判断が要る

### 案 C: PC 版 LINE + PC 側で録音

Windows PC で LINE 通話を受けて、PC の再生音とマイクをまとめて録音ソフトで録る。

- **長所**: 音質は最良に近い。フリーウェイは Windows なので環境が揃っている
- **短所**: **個人 LINE を店の PC にログインさせることになります**。個人のトーク履歴が店の PC に同期されるので、業務としてはおすすめしません

### LINE 通話についての率直な意見

現状の「個人携帯の LINE で日常やりとり」という運用のまま録音を挟むのは、正直あまり筋が良くないと思っています。

LINE で入ってくる予約の実態が「通話」中心なのか「テキスト」中心なのかで、話が変わります。**テキストのやりとりが主なら、録音の話は不要で、トーク画面のスクリーンショットを Claude に読ませるほうが早くて確実です。**

ここは訪問時に小出様に確認したい点です。

## 3. 固定電話は素直に解決する

### 受話器用録音アダプタ

受話器と電話機本体をつなぐカールコードの間に挟む小さな部品です。

- 電池も電源も不要
- 工事も契約も不要
- 自分の声と相手の声の両方が、部屋の反響なしに録れる
- **2,000 円台**で買える (エルパ TEA-041 など)

アダプタから出たプラグを IC レコーダーか PC のマイク端子に挿すだけです。電話音声としては最良の品質が取れます。

購入前の確認事項が 1 つあります。**お店の電話機の受話器コードが 4 極 4 芯かどうか**。今どきの電話機はほぼこれですが、古い機種だと違うことがあります。

### 費用

| 品目 | 費用 |
|---|---|
| 受話器用録音アダプタ | 2,000 円台 |
| IC レコーダー | 1 万円前後 (手持ちのスマホや PC で代用すれば 0 円) |
| 文字起こしソフト | **0 円** (ローカルで動く) |
| **月額** | **0 円** |

初期 1 万円から 1.5 万円、月額ゼロ。CLAUDE.md にある「クラウド、サブスク、月額を持ち込むと現場感に合わない」という方針に、これは合っていると思います。

### クラウド電話サービスという選択肢もあるが

MiiTel やカイクラのような、通話録音と文字起こしが最初から入ったサービスもあります。導入は圧倒的に楽です。

ただし:

- 月額が 1 ID あたり数千円かかる。**繁忙期が 7 月から 9 月に集中するフリーウェイでは、使わない 9 ヶ月分も払うことになります**
- 顧客の音声が外部サーバーに保存される
- 電話番号や回線の移行が絡む場合がある

**7 月から 9 月だけ契約して残りは止める**運用ができるなら選択肢に入ります。年間コストを試算して比べる価値はあります。訪問時に数字を出しましょう。

## 4. 文字起こしはローカルで無料

**faster-whisper** を使います。OpenAI の Whisper を高速化した実装で、Windows の PC 上で完結します。

- **顧客の音声がネットに出ません**。これが一番大きい。要配慮個人情報 (持病、服薬) が会話に出ても外部送信されない
- 月額ゼロ
- 初回だけモデルのダウンロード (約 3GB) に通信が要る。以降はオフライン

処理時間の目安は、CPU のみで音声の長さの 1 倍から 4 倍です。10 分の通話に 10 分から 40 分。繁忙期に 20 件溜まっても、夜のうちにまとめて回せば朝には終わっています。

### 精度の現実 (ここは正直に書きます)

Whisper large-v3 は日本語の書き起こしとしては現時点で最上位クラスですが、**電話音声という条件では落ちます**。

特に間違えるもの:

- **数字**。日付、時刻、人数、電話番号、金額。ここが一番危ない
- **固有名詞**。ポイント名、魚名、お客様の氏名
- **無音区間での作文**。何も喋っていない部分に、それらしい文を作ってしまうことがある

3 番目は `skills/call-log/scripts/transcribe.py` で対策済みです。無音検出を有効にして、直前の文脈への引きずりを切ってあります。

1 番目と 2 番目は**運用でカバーするしかありません**。だから台帳に「要確認」列があります。

### 固有名詞は辞書で改善できる

`skills/call-log/references/vocab.txt` に店名、コース名、ポイント名、魚名を並べてあります。ここに書いた語は、文字起こしの前に AI に渡されて、その表記に寄せてくれます。

**毎回間違える単語をここに足していくと、使うほど精度が上がります。** 現場が育てるファイルです。ポイント名 17 箇所は、川島が実名を把握していないので空にしてあります。訪問時に埋めましょう。

## 5. 保存先は Excel と Word を使い分ける

### Excel 台帳 (日常はこちら)

`通話ログ.xlsx` に 1 通話 1 行で溜めます。列はこうしてあります。

```
受付日時 / チャネル / お客様名 / 電話番号 / 用件 / 希望日 / 人数 /
コース / 経験・ランク / 要望・メモ / 要確認 / 対応者 / ステータス /
文字起こしファイル / 音声ファイル / 登録日時
```

繁忙期に効くのは検索と並べ替えです。「あの人なんて言ってたっけ」を 5 秒で引ける状態を作る。

**月別予約 Excel とは別のファイルにしてあります。** 既存の運用を壊さないためです。台帳から予約本体への転記は、人間が要確認を潰してから手でやる。ここは自動化しません。予約可否は空き状況だけでは決められない、という小出様の指摘そのままです。

列は自由に足して構いません。並べ替えても、独自列を挿しても、スクリプトは列名を見て書き込むので壊れません。

### Word 議事録 (込み入った時だけ)

クレーム対応や長い相談など、経緯を文章で残したい時はこちら。`skills/docx` が同梱済みなので、文字起こしから Word 文書を組み立てられます。

日常の予約電話をいちいち Word にする必要はありません。

## 6. 法律と同意の整理

### 録音そのものは適法

自社が当事者として自分の通話を録音する行為は、第三者による無断傍受とは性質が違うため、通信の秘密の問題は生じないという整理が一般的です。**相手の同意がなくても違法にはなりません。**

### ただし個人情報保護法は掛かる

録音データは内容から個人が特定できるので、個人情報として扱う必要があります。

個人情報保護委員会の見解では、**利用目的を通知または公表する義務は負うが、録音している旨を相手方に伝える義務までは負わない**とされています ([個人情報保護委員会 FAQ](https://www.ppc.go.jp/all_faq_index/faq1-q1-10/))。

### 実務としてどうするか

告知は法的義務ではありませんが、**やっておくことをおすすめします**。

- 冒頭で「お電話の内容は、お客様対応の品質向上のため録音させていただいております」と一言添える
- 迷惑電話やクレームの抑止にもなる

フリーウェイの規模なら、自動音声の設備を入れる必要はありません。電話に出た人が言うだけで足ります。

### 決めておくべきこと

1. **保存期間**。3 ヶ月なのか 1 年なのか。決めて、過ぎたものは消す。溜め続けるのはリスクだけが増えます
2. **アクセスできる人**。台帳と録音を誰が見られるか
3. **健康情報の扱い**。持病や服薬の話が出た通話は要配慮個人情報です。台帳の平文に書かず、別管理にする

## 7. 5 チャネルのうちどこまで届くか

CLAUDE.md にある 5 つの予約チャネルに対して、この仕組みがどこまで効くか。

| チャネル | 録音 | 備考 |
|---|---|---|
| 固定電話 | ◎ | アダプタで完全に解決 |
| 個人携帯の LINE (通話) | △ | スピーカー録音なら可能 |
| 個人携帯の LINE (テキスト) | 対象外 | スクショを Claude に読ませるほうが早い |
| 現場で口頭 | ○ | スマホのボイスメモで同じ流れに乗る |
| HP 予約フォーム | 対象外 | メール受信なので別の話 |
| じゃらん | 対象外 | 管理画面から取る話 |

**「電話と口頭で入ってくる予約が、テキストで検索できる状態になる」** が、このツールの正味の価値です。

CLAUDE.md にある「予約整理に 1 日 2 時間」のうち、電話由来の部分が短くなるはずです。どれだけ短くなるかは、実際に 1 週間回してみないと分かりません。そこは正直なところです。

## 8. おすすめの始め方

一度に全部やらないでください。

### 第 1 段階: ゼロ円で試す (今日から)

手持ちのスマホのボイスメモで、固定電話をスピーカーにして 2、3 件録ってみる。文字起こしに掛けて、**精度を自分の目で見る**。

ここで「使えない」と感じたら、機材を買う前に止められます。

### 第 2 段階: 固定電話に機材を入れる (精度に納得したら)

受話器用録音アダプタを買う。2,000 円台。音質が上がって精度も上がります。

### 第 3 段階: 台帳を業務に乗せる (1 週間回してから)

繁忙期前に、要確認欄の潰し方を含めた運用を固める。

### 第 4 段階: LINE 通話をどうするか決める

第 3 段階まで来て「電話は楽になった、LINE も欲しい」となったら、その時に Android 端末の話をする。先に決める必要はありません。

## 10. 訪問時に確認したいこと

1. **LINE で入る予約は、通話が主かテキストが主か**。ここで LINE 側の打ち手が変わります
2. **固定電話の受話器コードが 4 極 4 芯か**。アダプタが挿さるかどうか
3. **1 日に電話が何件入るか**。繁忙期のピークで
4. **録音の保存期間をどうするか**
5. **ポイント名 17 箇所の正式な呼び方**。辞書に入れます
6. **クラウド電話サービスの年額と、自前構成の差額**。繁忙期だけ契約する案の是非
