## 動画の核メッセージ

Claude Code を入れた人は世界中にいる。でもアウトプットの質には**100倍以上の差**がある。なぜか。

理由は2つしかない。

1. **環境**：Claude Codeに何の道具を持たせているか
2. **言語化能力**：Claude Codeに何をどう頼むか

このうち言語化能力は一朝一夕では身につかない。でも環境は今日30分で整う。

今日紹介する5つのツールは、入れた瞬間に Claude Code を別物にする。レベル1だった Claude Code が、一気にレベル10まで上がる。そういうツールだけを選んだ。

## なぜこの5つなのか ── 「Claude Code に5つの感覚を授ける」

Claude Codeはデフォルトでは「テキストしか扱えない頭脳」だけが入った状態。これに5つの感覚を後付けで授ける、それが今日のテーマ。

| ツール | Claude Codeに与える感覚 |
|---|---|
| **Playwright** | **目** ── Webサイトを見て触る能力 |
| **Exa** | **耳** ── Webから意味で情報を取りに行く能力 |
| **Context7** | **記憶の鮮度** ── 最新のライブラリ知識を常に持つ能力 |
| **Repomix** | **理解力** ── 巨大なコードベース全体を読み解く能力 |
| **Document Skills** | **手** ── PDF・Word・Excel・PowerPointを成果物として出力する能力 |

この5つが揃って初めて、Claude Code は「指示すれば仕事を完結させる存在」になる。1つでも欠けると、どこかで人間が手作業を挟むことになる。

## #1 Playwright ── Claude Codeに「目」を授ける

### Playwrightとは何か

Playwrightは、ブラウザを自動操作するための世界標準ライブラリ。Microsoftが2020年にリリースした。

ブラウザを開く、URLにアクセスする、要素をクリックする、フォームを入力する、スクリーンショットを撮る、ページの内容を読み取る ── こういう操作を、人間がマウスで触る代わりに、コードから指示できる。

### なぜ「世界標準」なのか

Playwrightの歴史を辿ると、世界標準である理由が分かる。

時代を遡ると、2017年にGoogleが Puppeteer というブラウザ自動化ツールを発表した。これが世界中で爆発的に普及し、ブラウザ自動化の事実上の標準になった。

ところが、Puppeteerの中心エンジニアたちが、後にGoogleからMicrosoftに移籍した。そこで彼らが作った後継ツールがPlaywrightだ。Puppeteerの課題、特に「Chromeしか正しく扱えない」「言語がJavaScriptだけ」という制約を全部解決した。

現在、Chrome・Firefox・Safari の全部を同じコードで動かせる。JavaScript・Python・Java・C# の4言語で書ける。これがPlaywrightが世界標準と言われる理由。

さらに重要なのは、最近話題のAIエージェント系のブラウザ操作ツール ── 例えば browser-use、Stagehand、Anthropic Computer Use ── これらは事実上ほぼ全部Playwrightをベースに作られている。AIがブラウザを操作する全ての土台がPlaywrightなんだ。

### Claude CodeにPlaywrightを授けると何ができるか

Playwrightを Claude Code のMCPとして登録すると、Claude Code に「目」が生まれる。

具体的にできることを5つ挙げる。

**1. 競合分析の自動化**
競合企業10社のWebサイトを Claude が自動で全ページ巡回する。各社のサービス内容・料金・お客様の声を全部スクリーンショット付きでまとめる。手作業なら半日かかる作業が10分で終わる。

**2. UI崩れの自動検証**
自分が作ったWebサイトの、PC幅・タブレット幅・スマホ幅 全部のスクリーンショットを撮って、文字が見えなくなってる箇所、ボタンが重なってる箇所を Claude が指摘する。

**3. 提案前のクライアントWeb巡回**
提案する前に、相手企業のサイトを全ページ巡回して、「お客様の声」「実績」「採用情報」から相手の本当の関心ごとを抽出する。商談の温度が変わる。

**4. 動作テスト**
作ったアプリの全画面・全ボタンを Claude が自動で触って、エラーが出ないか確認する。手動テストの工数が消える。

**5. リファレンスサイトの解析**
「このサイトのデザインが好きなんだけど」と URL を渡すと、Claude がフォント・色・余白・アニメーションを全部読み取って「このサイトと同じトーンで作って」が可能になる。

### Playwrightが入っていない Claude Code との差

入ってないと、Webサイトに関わる全ての作業で、人間がスクリーンショットを撮って Claude に渡す必要がある。1サイト10枚撮るとして、10社で100枚。これを手作業でやってる人と、Playwrightで一発でやる人。同じ Claude Code でもアウトプットの速度が10倍違う。

## #2 Exa ── Claude Codeに「耳」を授ける

### Exaとは何か

ExaはAI専用に作られた検索エンジン。Harvard出身のWill BrykとJeff Wangが2021年に創業した。

2026年5月、Andreessen Horowitz主導のSeries Cで2.5億ドル(約375億円)を調達し、バリュエーションは22億ドル(約3,300億円)。半年前の7億ドルから3倍以上に評価が跳ね上がった、今最も注目されているAIスタートアップの1つ。

GoogleやBingといった既存の検索エンジンとは、根本的に違う仕組みで動いている。

### Google検索とExaの根本的な違い

Googleは「キーワード」で探す。検索ボックスに入れた単語と、Web上の各ページに含まれる単語の一致を見て、関連性をスコアリングする。だから「ベイエリアでブログを書いているソフトウェアエンジニア」みたいな複雑な意図を表現した検索は、うまくいかない。

Exaは「意味」で探す。ニューラルネットワークでWeb上の各ページを「意味のベクトル」に変換して保存している。検索する時も、入力した文章の意味をベクトル化して、近いベクトルを持つページを返す。

結果として、「ベイエリアでブログを書いているソフトウェアエンジニア」という検索で、本当にそういうエンジニアの個人ブログが返ってくる。

これがどういう革命かというと、人物の検索・専門家の検索・特定領域の深い記事の検索 ── 既存検索エンジンが苦手だった全領域で、Exaが圧倒的に強い。

### 誰が使っているか

ExaはAI業界の裏方として既に広く使われている。10万人以上の開発者が利用中。

- **Cursor**(AIコードエディタ)
- **Notion / Notion AI**
- **Harvey**(法務AI)
- **Clay**(セールスインテリジェンス)
- **Databricks / AWS / Vercel / Hubspot / Monday.com**
- 多数のAIエージェント・Fortune 500企業

「あなたが使ってるAIサービスの検索結果、実はExaが提供してます」というケースが多い。

### Claude CodeにExaを授けると何ができるか

Exaを Claude Code のMCPとして登録すると、Claude Code に「耳」が生まれる。「情報を意味で取りに行く力」だ。

**1. 人物リサーチの破壊力**
商談前に相手の社長を調べる。Googleだと社名+名前で表面的な情報しか出ない。Exaだと、社長個人のブログ・インタビュー記事・SNS投稿・登壇録 全部出てくる。「ベイエリア在住で旅館経営をしてる元エンジニアの社長」レベルの複雑条件も引ける。

**2. 競合分析の深さが変わる**
「日本国内で介護向けAI研修をやってる中小企業」みたいな曖昧な検索が成立する。Googleでは絶対に出てこない情報が出る。

**3. 専門記事の発見**
特定分野の専門記事・論文・技術ブログを「意味」で集められる。例えば「LLMの幻覚を減らすRAG実装パターン」で検索すると、技術的に近い記事だけが返ってくる。Google検索だと広告と入門記事だらけで埋もれる。

**4. インスピレーション収集**
デザインのリファレンス・コピーライティングのお手本・営業トークのお手本、こういう「ニュアンス検索」が成立する。

### 本動画のハイライト ── 「Exa × NotebookLM 商談前リサーチ術」

ここが今日の動画で一番大事なパート。

普通の人がやってる商談前リサーチは、こうだ。
- 相手のWebサイトを見る
- 社名でGoogle検索
- 出てきた記事を3本ぐらい読む
- 終わり

これだと、相手のことを「表面しか知らない」状態で商談に臨む。

俺はこういうワークフローでやっている。

**ステップ1**: Exaで「相手の社長名 + 業界キーワード + 数年前の動向」を検索する。意味検索なので、ブログ・インタビュー・登壇録・古い記事まで全部引ける。

**ステップ2**: 出てきた記事URLを10本ほどコピーする。

**ステップ3**: GoogleのNotebookLMにそのURLを10本全部食わせる。NotebookLMは、長文資料を読み込んでQ&A可能な状態に変換するGoogle製のAIノートブックだ。

**ステップ4**: NotebookLMの「音声会議」機能を使う。これは、食わせた資料をAIの男女2人の声で「対談ポッドキャスト」として10分前後の音声に変換してくれる機能だ。

**ステップ5**: その音声を、移動中・通勤中・商談に向かう電車の中で聞く。

何が起きるか。

商談の場に着いた時、自分は「相手の人生15年分のストーリー」を耳から入れた状態で会える。「3年前にコロナで一度倒産しかけた時の話、本当に大変でしたね」とか、「2号店オープンの時の地元住民との交渉、あれ素晴らしかったですね」とか、初対面とは思えない深さで話せる。

相手の心の構えが180度変わる。「この人、俺のことをちゃんと知ってきてくれてる」と感じてもらえる。これは営業の根本を変える。

**この組み合わせがExa×NotebookLMの本当の威力**。Exaが「深い情報を集める」、NotebookLMが「集めた情報を耳から入れる」。

NotebookLM単体でも便利だが、Exaと組ませて初めて「人間が普通やらないリサーチ」が成立する。

## #3 Context7 ── Claude Codeに「記憶の鮮度」を授ける

### Context7とは何か

Context7は、プログラミングライブラリの**公式ドキュメント最新版**を、自動でClaude Codeに渡してくれるMCPサーバー。

Upstash社という、サーバーレスデータベースを提供している会社が作っている。MITライセンスのオープンソース。

### なぜ必要か ── LLMの「知識カットオフ問題」

ChatGPTもClaudeも、ある時点までのデータで学習している。これを「学習データのカットオフ」と呼ぶ。

例えば Claude Opus 4.7 のカットオフは2026年1月。つまり、2026年2月以降にリリースされたライブラリの新機能、API変更、廃止された機能、これらをClaudeは知らない。

何が問題か。

ReactやNext.jsのような人気ライブラリは、3ヶ月ごとに大きな変更がある。Claudeに「Next.js 16でこれを実装して」と頼んでも、Claudeは「Next.js 14時代の書き方」で答えてしまう。動かないコードが返ってくる。

これがLLMの根本問題で、多くのClaude Codeユーザーが知らないうちに「半年前の書き方」で開発してしまっている。

### Context7はどう解決するか

Context7は、9,000以上のライブラリ・フレームワークの公式ドキュメントを常時インデックスしている。Claude Codeが「Next.js 16のApp Routerについて教えて」と言うと、Context7が以下を実行する。

1. **resolve-library-id**: ライブラリ名(Next.js 16)を内部IDに変換
2. **get-library-docs**: 該当バージョンの公式docsから関連セクションを取得
3. Claudeに返す

ポイントは、ライブラリの**バージョン別**にドキュメントを保持していること。「Next.js 14の書き方」と「Next.js 16の書き方」を別物として返してくれる。

技術的にはこういう仕組みで動いている。
- 公式ドキュメントから コードスニペットと説明を抽出
- LLMで短い説明文とメタデータを追加
- ベクトル化して意味検索可能に
- 独自アルゴリズムで再ランキング
- Redisで高速キャッシュ

### Claude CodeにContext7を授けると何ができるか

**1. 最新書き方で常にコード生成**
Next.js 16、React 19、Tailwind v4、Supabase 最新版、全て公式docsの最新書き方で実装される。

**2. バージョン別の正確な指示**
「Next.js 14でやりたい」「Next.js 16でやりたい」を使い分けられる。マイグレーション作業で重宝する。

**3. 古いコードのデバッグが楽**
古いプロジェクトを触る時、「これNext.js 13で書かれてるけど、どこが古い書き方？」を即座に判定できる。

**4. ライブラリ選定の判断材料**
「TanStack QueryとSWR、最新版での違いは？」みたいな比較検討が、最新docs基準でできる。

### Context7が入っていない Claude Code との差

入ってないと、Claudeが「2026年1月までの知識で書く」状態のまま。これだと、3ヶ月後には半年前の書き方になり、半年後には1年前の書き方になる。永遠に「ちょっと古いコード」を量産し続ける。

特にPWA・SaaS開発、つまり最新ライブラリを使う領域では致命的。

## #4 Repomix ── Claude Codeに「理解力」を授ける

### Repomixとは何か

Repomixは、GitHubリポジトリでもローカルのコードベースでも、丸ごと1つのファイル(XML形式が主)に圧縮するツール。圧縮されたファイルをLLMに食わせることで、「コードベース全体を一度に理解させる」ことができる。

開発者は日本の Yamada Atsushi(yamadashy)氏。2024年にリリースされ、2026年5月時点でGitHub Star **約25,600**。最新バージョンは v1.14.0(2026年4月26日リリース)。TypeScript製、MITライセンス。日本人開発のOSSとしては世界トップクラスの注目度。

### なぜ必要か ── LLMの「コンテキスト窓問題」

Claude Codeで大きなプロジェクトを触る時、必ず直面する問題がある。

「このプロジェクト全体を理解した上で、リファクタしてほしい」と頼みたい。でも Claude は、プロジェクト内のファイルを1つずつ読むしかない。プロジェクトが50ファイル100ファイルあると、Claudeが全体像を掴むのに時間がかかるし、コンテキスト窓を圧迫する。

「全体を一度に見せる」方法が必要だった。それがRepomix。

### Repomixの何が凄いか

**1. 1コマンドでコードベース全体をXML化**
```bash
npx repomix
```
これだけで、カレントディレクトリの全コードファイルを1つのXMLファイルに圧縮する。

**2. AIに最適化された構造**
出力XMLの先頭に「AI向け説明文」が自動挿入される。Claudeが「これはどういう構造のリポジトリか」を最初に理解できる。

**3. トークン数を約70%削減**
`--compress` オプションを使うと、Tree-sitter(コード構文解析ツール)で重要な部分だけ抽出し、トークン数を約70%減らせる。Claude の長文コストを劇的に下げる。

対応言語は JavaScript / TypeScript / Python / Rust / Go / C / C++ / C# / Ruby / Java / PHP / Swift など主要言語ほぼ全て。

**4. プライバシーファースト**
全てローカル実行。コードが外部サーバーに送信されることは一切ない。社内プロジェクト・クライアントコードでも安心して使える。

**5. リモートリポジトリ対応**
GitHubのURLを渡すだけで、リモートリポジトリも圧縮できる。
```bash
npx repomix --remote https://github.com/owner/repo
```

### Claude CodeにRepomixを授けると何ができるか

**1. 巨大プロジェクトのコードレビュー一発**
他人のリポジトリ全体を1ファイルにしてClaudeに渡す → 「このコード、設計上の問題点を5つ挙げて」が30秒で終わる。

**2. レガシーコードの移植**
古いPHPで書かれたシステム全体をRepomixで1ファイルにし、Claudeに「これと同じ機能をNext.jsで書き直して」と頼む。マイグレーション工数が激減する。

**3. ドキュメント生成**
リポジトリ全体を渡して「READMEを書いて」「APIリファレンスを生成して」が可能になる。

**4. バグ調査**
特定のバグについて、関連ファイル全部を渡せば、Claudeが因果関係を一発で特定できる。

**5. 学習用にOSSを読む**
「Next.jsのソースコード、ざっくり構造を教えて」みたいな学習用途で、巨大OSSを「教師」として使える。

### Claude Codeのコンテキスト管理が一段階上に行く

Repomix無しの Claude Code は「ファイル1つずつ読む」スタイル。Repomix有りの Claude Code は「プロジェクト全体を一度に把握してから動く」スタイル。

これは作業の質に直結する。「全体を見ていない人」と「全体を見てから動く人」の差そのものだ。

## #5 Anthropic公式 Document Skills ── Claude Codeに「手」を授ける

### Document Skillsとは何か

Anthropic公式の「Skill」として配布されている、PDF・DOCX・XLSX・PPTX の4ファイル形式を生成・編集・読み取りするためのスキル4本セット。

2025年10月16日にAnthropicが「Claude Skills」を発表した時、最初に公開された公式スキルの中に含まれていた。GitHubの`anthropics/skills`リポジトリに公開されている。

### なぜAnthropic公式が出したか

LLMで仕事を完結させようとすると、最後の最後で「成果物としてWord・Excel・PowerPoint・PDFが必要」という壁にぶつかる。

これまでは、Claudeが文章を生成→人間がコピペしてWord/Excel/PPT に貼り付ける、という二度手間が必要だった。

Anthropicが「これを完全自動化するスキル」を公式で提供することで、Claudeが「最初から完成形のオフィス文書」を出力できるようになった。

### 4つのスキルの中身

**1. pdf スキル**
- PDFの生成・編集
- フォームへの自動記入
- データ抽出(表・テキスト)
- PDFの分割・結合
- 公式ライブラリ全体で**最も使われている**スキル

**2. docx スキル**
- Wordファイル(.docx)の生成・編集・読込
- スタイル・見出し・テーブル対応
- **変更履歴(Track Changes)** にも対応
- 校閲業務に強い

**3. xlsx スキル**
- Excelファイル(.xlsx)の生成・編集
- **数式・書式・ピボットテーブル**を保持
- データ分析・可視化対応

**4. pptx スキル**
- PowerPoint(.pptx)の生成
- レイアウト・テンプレート・チャート対応
- プレゼン資料の自動生成

### Claude CodeにDocument Skillsを授けると何ができるか

**1. 提案書・報告書の自動生成**
クライアントからのヒアリング内容 → そのままWord提案書として出力。フォーマット・体裁完璧。

**2. 請求書・見積書の自動発行**
案件情報を渡す → 整った形式の請求書PDFが瞬時に出る。手動Excel入力が消える。

**3. 経費・売上集計**
領収書・取引データを渡す → Excelで月次集計、ピボットテーブル付き、数式入り。

**4. 研修配布資料**
研修内容のメモ → そのままWord配布資料化、目次・図表入り。

**5. 契約書ドラフト**
案件条件のメモ → 契約書のドラフトをWord形式で生成、変更履歴付きで送付。

### 既存ワークフローへの影響

これまでClaude Codeで「文章作って」と頼んでも、出力はMarkdownかテキスト。それをユーザーが自分でWord/Excel/PPTに貼り直す必要があった。

Document Skills導入後は、Claudeが「最初からWord/Excel/PPT/PDFで出す」。中間のコピペ作業が完全に消える。

これは作業時間で言うと、1案件あたり30分から1時間の節約。月10案件回す人なら、月5時間〜10時間の節約になる。

### Anthropic公式である意味

サードパーティ製の似たツールは無数にある。しかしAnthropic公式は、

- **Claude本体のアップデートと同期**して進化する
- **互換性が保証**される
- **無料**
- **APIキー不要**

長期で使うなら、Anthropic公式一択。

## 5つ揃った時の威力 ── 全部繋がる

5つを個別に使うのではなく、組み合わせる時に真価が出る。具体例で示す。

### シナリオ：新規クライアント案件「商談→提案→納品」

**STEP 1 ── 商談前リサーチ (Exa + NotebookLM)**
Exaで相手社長の記事10本収集 → NotebookLMで音声化 → 通勤中に聞く。商談時には相手の人生15年を把握済み状態。

**STEP 2 ── 競合サイト分析 (Playwright)**
商談で得た「相手の競合」のWebサイト5社を Playwright で全ページ巡回 → スクショ+テキスト全部取得。

**STEP 3 ── 提案書ドラフト作成 (Context7)**
新しいWebサイトを Next.js 16 で作る前提で、Context7 が最新の Next.js docs を参照しながら技術提案を作成。

**STEP 4 ── 既存システム解析 (Repomix)**
相手の既存システムリポジトリを Repomix で1ファイル化 → Claude が全体構造を理解 → 「ここを改善できる」を抽出。

**STEP 5 ── 提案書として納品 (Document Skills)**
全部の調査結果を **PowerPoint提案書 + Excel工数表 + Word契約書ドラフト** として一発出力。手動の貼り付け作業ゼロ。

これが、Claude Codeを5つで武装させた時のワークフロー。**1人で大手コンサルファーム1チーム分の仕事ができる**。

## レベル1 と レベル10 の具体的な差

実際にどれぐらい差が出るか。1日の業務で比較する。

### レベル1のClaude Codeユーザー(5つ無し)
- 朝：競合サイト分析 → ブラウザ手動・スクショ手動 → 3社で1時間半
- 昼：提案書作成 → Claudeに文章書かせて→自分でPPTに貼る → 3時間
- 夕：見積書作成 → Excelに手入力 → 30分
- 夜：技術調査 → Google検索 → 古い情報に振り回される → 1時間

**合計**: 6時間 / 1案件

### レベル10のClaude Codeユーザー(5つ全部入り)
- 朝：Playwrightで競合10社全自動分析 → 15分
- 昼：Document Skillsで PPTX 提案書一発生成 → 30分
- 夕：Document Skillsで Excel 見積書一発生成 → 5分
- 夜：Context7 + Exa で最新docs + 業界記事収集 → 15分

**合計**: 1時間5分 / 1案件

**1案件あたりの差: 約5時間。月10案件なら月50時間の差。**

これが「環境を整える」という言葉の本当の意味。
